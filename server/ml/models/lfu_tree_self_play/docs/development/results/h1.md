# H1：同じ終局軌跡群を共有・再計算した結果

2026-10-26、Apple M1・メモリ16 GiB上でCPUとMPSを比較しました。両deviceで、共有方式と再計算方式の生成データ・リターン・学習上の重みが一致しました。共有方式は生成時間・推論盤面数・環境遷移数を削減しました。メモリ削減を支持する結果ではありません。

## 条件と再実行

[比較ガイド](../../guides/shared-paths.md)の既定条件で実行しました。幅64・残差4ブロック、float32の固定モデル、3 seed × 4根の12木、幅4・ランダム2段分岐、合計192終局葉です。両方式にbatch上限32・同時単位上限32・RSSとdeviceそれぞれ2 GiBの上限を与え、各回を別プロセスでウォームアップ1回後に計測しました。3回の計測では方式の順序を交互にしました。

```sh
uv run --locked lfu-tree-self-play verify-shared-paths --device cpu --output artifacts/h1-cpu.json
uv run --locked lfu-tree-self-play verify-shared-paths --device mps --output artifacts/h1-mps.json
```

パッケージのディレクトリで、出力先の`artifacts`を作成してから実行します。生のレポートは[CPU](h1-cpu.json)と[MPS](h1-mps.json)に保存しています。モデルのSHA-256、根の着手履歴・seed・分岐位置、Python/PyTorch/OS情報、各回の費用・batch分布・待機時間を含みます。両deviceで使用したモデルファイルのSHA-256は同じです。

## 観測結果

時間とメモリは3回の中央値です。件数は全反復で一致しました。速度比は各反復の「再計算時間 ÷ 共有時間」の中央値です。

| 指標 | CPU・共有 | CPU・再計算 | MPS・共有 | MPS・再計算 |
| --- | ---: | ---: | ---: | ---: |
| 生成時間（秒） | 1.499 | 3.321 | 2.988 | 5.373 |
| 推論盤面数 | 4,069 | 10,699 | 4,069 | 10,699 |
| 物理推論batch数 | 554 | 944 | 554 | 944 |
| 環境遷移数 | 4,249 | 10,699 | 4,249 | 10,699 |
| RSS標本ピーク（bytes） | 415,842,304 | 416,432,128 | 584,335,360 | 576,618,496 |
| deviceピーク（bytes） | — | — | 2,197,248 | 2,197,248 |

速度比はCPU **2.237倍**（範囲2.201〜2.247）、MPS **1.798倍**（範囲1.796〜1.816）でした。推論盤面数は61.97%、環境遷移数は60.29%減少しました。

参照木との一致に加え、方式間の出力同士も比較しました。盤面・行動・木構造・ID・乱数記録・終局結果・リターン・重みは完全一致です。方式間の`old_value`最大絶対誤差はCPU `9.313225746154785e-10`、MPS `0`、保存log probabilityの最大絶対誤差は両deviceとも`0`でした。いずれも正本の許容差`1e-6`以下です。

## 解釈の範囲

生成時間はモデルと固定入力の準備、完成後の検証・リターン集約、永続化を含みません。RSSはモデルと固定入力を保持するプロセスの標本ピークで、区間内の瞬間最大値や生成だけの増分ではありません。deviceピークはウォームアップ後にリセットしたPyTorchのallocation counterです。

今回の条件ではH1の生成費用削減が確認できました。独立自己対戦Aとの棋力比較、学習を含む総時間、保存容量の削減を検証した結果ではありません。小型モデルの短い計測であり、CPUとMPSの速度差や他の構成へそのまま一般化しません。
