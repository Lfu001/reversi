# 開発計画

研究計画を実装するための開発段階、依存関係と合格条件を定義します。ここに記載した開発項目には未実装のものも含まれ、タスクの記載自体は実装完了や検証ゲート通過を意味しません。現在の利用方法は [パッケージの README](../../README.md)、仮説・数理・比較条件は [研究計画](../research/README.md) を参照してください。

旧計画を前提とする `lfu_mcts_grpo/dev` は実装基盤にせず、`lfu_tree_self_play` を独立に構築します。共通ライブラリや旧実装の一部を利用する場合は、契約テストまたは参照実装との一致試験を通過したものだけを採用します。

## 全体像

- [実行モデル](execution-model.md)：収集、学習、評価、再開の流れ
- [検証条件](verification-gates.md)：実験の次工程へ進む条件

実験条件の数値や数式は [実験計画](../research/experiment-plan.md) を正本とします。各タスクには個別の成果と合格条件を記載し、ゲート全体の条件はリンク先で確認します。

## 計画内の識別子

文書間で項目を参照するため、開発段階を `M0`〜`M9`、個別タスクを `T01`〜`T54`、次工程へ進むための検証条件を `G0`〜`G8` と表します。いずれもこの研究計画内の識別子です。API の引数、保存形式の version、実行状態を表す値ではありません。

| [M3：学習](milestones/03-learning.md) | advantage、loss、更新 | T18〜T22 | ゲーム・数理検証、保存・再開検証 |

収集と学習の一部は固定データを使って並行できます。実データとの接続には保存・再開の検証が必要です。拡張は一要因ずつ基礎条件と比較します。

## 完了条件

- 検証条件ごとの結果が保存されている。
- 比較実験が成功、未到達、不成立のいずれかとして完結している。
- 結果から設定、dataset、checkpoint、評価対局、集計入力を追跡できる。
- 代表 run と図表を保存済み manifest から再生成できる。
- 仮説ごとの結論と主張できない範囲が明記されている。
