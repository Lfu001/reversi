# 終局軌跡の木状共有による自己対戦学習：実験ロードマップ

## 位置付け

この文書は、[改訂済み実験計画](../../lfu_mcts_grpo/dev/README_ja.md)を、検証可能な研究開発タスクへ分割したロードマップである。型定義、関数シグネチャ、具体的なファイル分割、デザインパターンは各タスクの設計時に決め、この文書では固定しない。

現行の `lfu_mcts_grpo/dev` 実装は旧計画を前提としており、新実験の実装基盤として再利用しない。新実験は `lfu_tree_self_play` 配下にclean-roomで構築する。共通ライブラリや旧実装の一部を利用する場合も、契約テストまたは参照実装との一致試験を通過したものだけを採用する。

この文書は確認実験の結果を示すものではない。タスクが完了しても仮説が支持されるとは限らず、不成立や未確認も正規の研究成果として扱う。

## 目的

次の仮説を混同せずに検証できる、再開可能で再現可能な実験系を構築し、A/B/C/Dの本実験と結果依存の拡張研究を実行する。

- H1：共通経路の計算・保存を共有すると、所定の終局軌跡群の生成コストが下がる。
- H2：同一局面の兄弟分岐を終局結果で比較すると、通常の終局リターンによる更新より有効な学習信号を得られる。
- H3：相関、多様性、木管理、学習コストを含めても、目標棋力への総コストが下がる。

## 全体原則

1. 教師信号は実際に終局まで進めた結果とし、途中局面の予測Q値で代用しない。
2. A/B/Cでは探索をデータ生成の前提にしない。MCTSは比較群Dに隔離する。
3. 正しさを確認する参照実装を先に作り、最適化版は参照結果との一致を必須とする。
4. 収集ラウンド中はπ_oldを固定し、収集、学習、評価を別の処理段階として扱う。
5. 学習、調整、最終評価のseedと開始局面を分離する。
6. 完了した対局または木だけを公開し、checkpointとデータ消費位置を同じmanifestで管理する。
7. Pilotで決める値は本実験前に機械可読な設定へ固定し、変更は別実験として扱う。
8. 拡張研究では一度に一要因だけを変更し、基礎実験の結果を上書きしない。

## 実行フロー

1. 設定内容とseed集合からexperiment IDを確定する。
2. ラウンド開始時のcheckpointをπ_oldとして固定してデータを収集する。
3. 完了データを検証し、atomicにdatasetへ公開する。
4. manifestで固定したデータを1 epochだけ学習し、新しいcheckpointを確定する。
5. 確定checkpointだけを調整用集合で評価する。
6. 累積収集・学習時間が評価境界へ達した後の最初の安全な更新境界で保存・評価する。
7. 最終評価集合はモデル選択やハイパーパラメータ調整に使用しない。

障害時は、収集中なら未完成単位だけを破棄し、学習中なら直前の確定checkpointへ戻り、評価中なら同じcheckpointとseedで評価だけを再実行する。設定不一致やmanifest不整合は自動補正せず、実行を拒否する。

## 検証ゲート

### G0：ゲームと数理の意味検証

- 既知局面で合法手、着手、強制パス、終局、勝敗が一致する。
- 黒視点結果と着手者視点への変換が一致する。
- θ=π_oldでimportance ratioが1になる。
- 同結果の兄弟群でleave-one-out advantageが0になる。
- 黒・白それぞれで、列挙値とMonte Carlo期待値・条件付き方策勾配が許容誤差内で一致する。
- 共有ありと再計算で、生成データとlossが一致する。

G0を通過するまで、収集システムの性能最適化を開始しない。

### G1：データ生成と永続化

- H=0、H=1、早期終局、強制パスを含む分岐予定が仕様どおり動く。
- 同一手を引いた兄弟標本も独立した終局試行として保存される。
- 子孫数が異なっても、再帰的な等重み集約が一致する。
- 各分岐後の経路重みの合計が親の重みに一致する。
- 保存と読込のround-tripで意味内容が完全に一致する。
- 任意の処理境界で停止しても、再開後に欠落や二重消費がない。

G1を通過するまで、保存データをtrainerへ接続しない。

### G2：最小End-to-End

- 小型モデルと小予算でA/B/Cが利用可能な単一デバイス上で完走する。
- 収集、保存、学習、checkpoint、評価、再開が一巡する。
- 非合法手が抽出されず、NaNとInfがなく、主要メトリクスが記録される。
- 同じ設定とseedで、データ識別子と処理系列が再現される。

G2を通過するまで、学習信号の比較実験を開始しない。

### G3：学習信号の小規模比較

- 同一木と同一初期モデルからB/Cを別々に更新できる。
- 構成した小例で、勝つ枝の確率が期待方向へ変化する。
- KL、clip率、合法手確率差、期待リターン変化を黒・白別に記録する。
- A/B/Cを3 seedの同一短時間予算で完走する。

CがBを上回らなくても実装失敗とは決めず、追加効果未確認として記録する。

### G4：Pilotと設定凍結

- バッチ、同時木数、メモリ上限、ラウンド当たりの収集量を実測する。
- 目標棋力、総予算T、評価局数、seed一覧を固定する。
- 比較群で共有するモデル、optimizer、評価条件を固定する。
- 機械可読な設定とそのハッシュを保存する。

G4後の変更は新しいexperiment IDを必要とする。

### G5：A/B/C本実験

- 5 seed以上を同一総予算で完走する。
- 到達率、制限付き到達時間、同予算score、学習曲線面積を全seedで報告する。
- H1、H2、H3を個別に判定する。
- 未到達seedを除外しない。
- 分岐段数と位置選択のアブレーションを条件を揃えて実施する。

### G6：AlphaZero型D

- 小局面で参照MCTSが列挙結果と一致する。
- 高速版が参照版と固定seedで一致するか、事前定義した許容差内に収まる。
- 符号、終局、訪問数、ノイズ、並列化、batch化を個別に検証する。
- 探索なし評価と同一対戦時間予算評価を分ける。

### G7：拡張研究

各拡張は独立した設定、seed、成果物を持ち、一度に一要因だけを変更する。拡張結果を基礎実験へ遡及適用しない。

### G8：再現性確認

空の出力先から、凍結設定とmanifestだけを使って代表runを再実行し、dataset、checkpoint系列、評価結果、集計表を再生成できることを確認する。

## マイルストーン間の依存

`M0 → M1 → M2/M3 → M4 → M5 → M6 → M7 → M8 → M9` を基本順序とする。M2とM3の内部では、保存済みfixtureで実装できる学習タスクを収集性能の最適化と並行できるが、実データ接続はG1通過後に限る。M7の参照MCTSはG0通過後に着手できるが、Dの本比較はM6の基礎結果とDのG6通過後に限る。

M8は全項目をタスク一覧へ含めるが、基礎結果を踏まえて個別に開始する。複数の拡張を一つのrunへ同時投入しない。

## 完了の定義

ロードマップ全体の完了は、次をすべて満たした状態とする。

- G0〜G8の結果が保存されている。
- A/B/C/Dの凍結設定による本実験が、成功・未到達・不成立のいずれかとして完結している。
- 実施対象となった拡張が、一要因ずつ基礎条件と比較されている。
- 任意の結果を設定、dataset、checkpoint、評価対局、集計入力まで追跡できる。
- 代表runと全図表を保存済みmanifestから再生成できる。
- 仮説ごとの結論と主張できない範囲が最終報告に明記されている。
